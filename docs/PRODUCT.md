# dsh Chat 产品梳理

> 目标：把 dsh Chat 当成一个完整 IM 产品来审视，而不是"功能堆"。本文记录产品结构、能力边界与后续路线。

## 1. 产品定位

dsh Chat 是 **DeepSeek Harness 的去中心化点对点即时通信插件**：无需账号服务器，靠房间名 + 口令派生中继主题，消息与文件端到端加密。既服务人与人，也服务人与 agent（`@chat` 自动回复、`chat_dispatch` 派活）。

## 2. 信息架构

```
侧栏（聊天列表）
├── 顶部：品牌 / 通知中心 / 全局搜索 / 新建群聊
├── 会话筛选：全部 · 未读 · 群组 · 已归档
├── 会话列表（置顶优先，行内 ⋯ 管理）
└── 底部：通讯录入口 + 个人资料卡（头像/昵称/签名/Agent ID → 设置）

主区域
├── 聊天页：头部（会话信息/成员/菜单）+ 搜索条 + 消息流 + 输入区
├── 通讯录页：发现目录 / 按 Agent ID 添加 / 通讯录 / 连接请求
├── 通知中心：未读会话 / 提到我
└── 设置页：个人资料 / 当前会话 / 桌面通知 / 发现与隐私 / 房间与中继 / 关于

浮层：邀请码、新建群聊、成员、会话设置、群资料、资料卡、转发、图片灯箱、全局搜索、快捷键
```

## 3. 能力清单

| 领域 | 已有能力 |
| --- | --- |
| 通信 | 房间 + 口令、端到端加密、ntfy / 自建中继、断线重连、正在输入、在线状态 |
| 消息 | 文本、图片/文件（≤10MB，加密传输）、引用、表情回应、编辑、撤回、转发、多选批量操作、富文本（链接/粗体/代码）、未读分隔、@提及 |
| 会话 | DM / 群聊、未读与已读回执、置顶、静音、归档、清空本机记录、重命名、退出 |
| 群 | 成员列表、群资料（名称 + 公告，广播同步）、邀请码 |
| 社交 | 公共发现目录、按 Agent ID 添加、连接请求、通讯录、资料卡（签名/Agent ID） |
| 输入 | 草稿按会话保存、拖拽/粘贴发送、上传状态、失败重试、快捷键（⌘K/⌘F/Enter/Esc/?） |

## 4. 技术结构

- **Host**（Node ESM，零依赖）：`peerchat`（房间状态机）、`relay`（ntfy/自建）、`crypto`（AES-256-GCM）、`store`（JSON/JSONL 持久化）、`social`（发现/收件箱）、`chats`（会话列表）、`routes`（HTTP API）、`bridge`（外部 agent 桥接）、`mcp`（stdio MCP）
- **Client**（单文件 Web 模块）：三处 slot 注册（侧栏图标 / 主面板 / 设置分区），数据全部来自 Host HTTP API
- **测试**：`test/smoke.mjs`（94 项 Host 逻辑）、`test/mcp-smoke.mjs`、jsdom 渲染回归（消息/附件/搜索/多选/群资料/通知/双语/设置 slot）

## 5. 已知边界（有意为之）

1. **群管理去中心化**：没有服务器裁决成员权限，房间口令即入场券；"移除成员"无法真正吊销已分发口令，因此不提供伪安全的管理员/踢人。
2. **附件存储**：公共 ntfy 附件约 3 小时过期；本机会缓存已下载文件，过期后仅影响未缓存设备。
3. **消息窗口**：内存/搜索默认最近 400 条（每会话），更早历史仍在 JSONL 文件中但未加载。
4. **多设备**：配置与已读游标是本机状态，不做跨设备同步。
5. **单会话在线**：同一时刻只订阅一个房间，切换会话即切换房间。

## 6. 后续路线

- 群头像与成员角色（在协议层广播，仍不做"踢人"假安全）
- 消息虚拟列表 / 更早历史分页
- 附件断点续传与上传进度
- 无障碍：完整键盘导航与读屏实测
- `client.js` 模块拆分（目前已 8500+ 行）
