# dsh Chat v4.0 UI/UX 差距审计

> 审计基线：v3.0.3（HEAD）+ 正在进行的 v4.0 工作区改动（2026-11-11）。功能级能力矩阵见 [COMPETITIVE.md](./COMPETITIVE.md)；本文只看**交互与体验细节**，不重复那份清单。
> 方法：读 README、PRODUCT.md、`client.js` 结构（单文件 ~1 万行、三处 slot、`dchat-*` 设计系统）+ 对照 Telegram / WhatsApp / Signal / Slack / Discord 的常见交互。
> 说明：v4.0 已排期/进行中的项（静音真正生效、Emoji 选择器、消息置顶、隐私三开关、Logo 重做）不在下面 15 条内；本文针对的是"下一层"交互差距。正在并行修改 `client.js`，个别"现状"可能已随最新代码前移，落地前请以工作区为准。

## 一、消息操作与手势

### 1. 消息操作入口只有 hover / focus，触屏不可达
**现状**：`MessageRow` 的操作 toolbar 只由 `.dchat-row:hover .dchat-actions` 与 `:focus-within` 显示；消息行本身不可聚焦，也没有 `onContextMenu` 与长按逻辑，触屏用户无法稳定唤出回复/回应/转发/撤回。
**对标**：Telegram、WhatsApp、Signal 长按弹菜单；Slack hover 工具栏 + 右键；Discord 右键菜单。移动端主流做法都是长按（约 480ms）+ 触觉反馈。
**建议**：补 `onContextMenu` 与统一长按手势（pointerdown 480ms，滚动/位移取消）；`@media (hover:none)` 时每条气泡常显一个"⋯"；桌面右键、长按、hover 菜单复用同一份 items。
**优先级**：P0（移动端目前无法可靠操作消息）。

### 2. 引用回复块不可点击跳转
**现状**：`.dchat-quote` 是纯 `div`；引用的原消息不在本地窗口时只显示「引用的消息不在本机窗口内」，没有任何定位入口。
**对标**：Telegram、WhatsApp 点引用跳到原消息并高亮；Signal 滚动定位；Slack 点引用跳到对应消息/线程。
**建议**：quote 改为 button，复用现有 `pendingJump` + 扩窗 + `/messages?before` 的自动加载定位链路，命中后高亮 1.2s；搜索结果、转发来源共用同一跳转管线；「quoteUnavailable」只保留为加载失败兜底，不再作为默认体验。
**优先级**：P1。

### 3. 缺少逐条投递状态与离线出站队列
**现状**：发送失败只有顶部 `dchat-send-error` 提示，消息未进列表；没有 pending/时钟/失败态，也没有断网重发；多选删除/转发同样没有失败重试。
**对标**：WhatsApp 时钟→单勾→双勾、失败可重试；Telegram 云朵/时钟；Slack/Discord 失败重发。
**建议**：本地乐观插入 `status:"sending"` 气泡（临时 id），成功后用 Host 返回的 seq 替换；失败保留气泡 +「重试 / 删除」；网络恢复后自动重发内存 outbox（仅本机，不新增协议）。
**优先级**：P1。

## 二、会话列表管理

### 4. 行级入口只有「⋯」大面板，没有右键 / 长按 / 滑动速操作
**现状**：会话行只有 `dchat-chat-more` 按钮，点开的是会话设置浮层；置顶、静音、归档、清空都要先进面板再操作，没有右键、长按、滑动。
**对标**：WhatsApp 会话行左滑归档/删除、长按菜单；Telegram 长按/右键菜单；Slack 右键频道菜单；Discord 右键菜单。
**建议**：抽出 `ChatRowMenu`（与面板同一份 items），支持右键、长按、`Shift+F10`；移动端补左滑（归档/静音）与右滑（标未读）；危险操作二次确认。
**优先级**：P1。

### 5. 没有「标为未读」，草稿只存不露
**现状**：进入会话即已读；草稿按房间写 localStorage，但会话行 preview 只显示 `lastText`，看不到草稿；也没有手动标记未读。
**对标**：Telegram 会话菜单「标为未读」；WhatsApp preview 前加「草稿:」；Slack 草稿用铅笔标记；Discord 草稿提示。
**建议**：本地游标支持 `markUnread`；preview 优先显示 `草稿: …`（斜体/品牌色）；未读 badge 区分「普通未读」与「有人 @我」（双色或 @ 角标），与通知中心口径一致。
**优先级**：P1。

## 三、搜索

### 6. 会话内搜索是「过滤流」，不是「结果面板」
**现状**：`searchActive` 直接把消息流过滤成命中项，搜索条只显示条数；没有命中词高亮、没有上/下条、没有上下文片段，Esc 退出后位置丢失。
**对标**：Telegram 结果列表 + 上/下跳转；WhatsApp 命中高亮 + 结果列表；Slack 侧栏结果面板；Discord 搜索结果面板。
**建议**：搜索条加「↑/↓ + n/N」与命中高亮；结果以列表展示（发送者/时间/一行上下文），点击定位并高亮；Enter、Shift+Enter、⌘G 切换命中，Esc 回到进入搜索前的滚动位置。
**优先级**：P1。

### 7. 全局搜索弱于对标
**现状**：⌘K 面板只展示会话与最多 30 条消息；没有过滤器、没有键盘上下选择、没有最近搜索、没有分页。
**对标**：Slack 搜索 operators（`from:` `in:` `before:` `has:link`）+ 筛选 chip；Telegram 全局 tab（会话/消息/文件）；Discord 过滤条件。
**建议**：结果按「会话 / 消息 / 媒体」分 tab，加常用 chip（人、日期、媒体、@我）；↑↓ + Enter 选择；记录最近 5 次搜索；消息结果分页；与引用/置顶共用跳转管道。
**优先级**：P1。

## 四、输入区与附件

### 8. @ 提及没有自动补全，也没有命令入口
**现状**：`@昵称` 只在渲染时高亮（`.dchat-mention`）；输入过程中没有候选列表，`@all` 也只能手打；没有 `/` 命令面板，agent 能力（`chat_ask` / `dispatch` / `invite`）只能靠记文本。
**对标**：Telegram、Slack、Discord 输入 `@` 弹成员列表（↑↓ + Enter/Tab 选择，Esc 关闭）；Slack `/` 命令面板；Telegram 命令菜单。
**建议**：监听文本光标前的 `@` 前缀弹成员候选（头像 + 昵称 + 在线），Enter/Tab 插入、Esc 关闭；`@all` 单独展示并提示影响范围；`/` 弹命令面板，命令词与普通文本可混排。
**优先级**：P1。

### 9. 附件没有「待发送托盘」，上传不能排队
**现状**：附件按钮一次只选一个文件（`files[0]`）；拖拽/粘贴可多文件但逐个上传，期间输入区没有发送前预览、说明文字、删除或重排；图片没有压缩/缩略图。
**对标**：Telegram 附件面板 + 发送前预览；WhatsApp 多图网格 + 说明文字；Slack 拖拽即缩略图 tray；Discord 附件队列。
**建议**：选择/拖入后先进待发送 tray（缩略图、大小、删除、逐项进度、失败重试），统一发送；多文件并发 2–3 个；图片按长边 1920 压缩并生成缩略图；失败项留在 tray。
**优先级**：P1。

## 五、通知与未读

### 10. 通知不可点、不合并、无提醒分级
**现状**：`new Notification(...)` 没有 `onclick`，点通知只聚焦窗口、不定位消息；同一会话短时间多条会连弹；提醒只有全局「桌面通知/声音」开关，没有「仅 @我」、免打扰时段、按会话提醒级别（静音标记 v4 刚接上，但仍无级别）。
**对标**：WhatsApp、Telegram 点通知直达会话和消息；Slack、Discord 每频道「全部 / 仅提及 / 静音」；Slack 免打扰时段；Signal 单聊通知可关。
**建议**：`onclick` → `switchChat + pendingJump`；5s 内同会话合并为「昵称 ×N」；会话菜单加提醒级别（全部/@我/静音）；设置加免打扰时段；v4 静音判断收敛为一个 `shouldNotify(chat, message)`。
**优先级**：P1。

## 六、群管理与隐私

### 11. 群管理缺搜索/批量/确认，邀请码缺有效期与二维码
**现状**：成员面板只能逐行操作（设/取消管理员），没有成员搜索、批量选择、角色变更确认；邀请码是纯文本，无过期、撤回、使用次数；没有二维码。
**对标**：Telegram 成员搜索 + 权限确认 + 可撤销邀请链接；WhatsApp 群邀请链接重置；Slack 成员管理/访客；Discord 角色 + 审计日志。
**建议**：成员搜索 + 按在线/角色筛选；角色变更弹确认，本地记录「谁在何时改了什么」；邀请码带 `expiresAt / maxUses` 与「重新生成」；邀请码纯前端渲染成 QR。
**优先级**：P1。

### 12. 隐私：缺本地屏蔽/举报，回执互惠没说清
**现状**：隐私只有「发现目录」+ v4 三项开关；没有屏蔽/举报；关闭已读回执后没有提示「你也看不到对方的回执」；没有按联系人例外。
**对标**：Signal、WhatsApp、Telegram 的屏蔽与举报；WhatsApp 关闭回执的双向提示；Signal 按联系人例外。
**建议**：本地屏蔽名单（隐藏其消息、拒收 DM、退出其房间），举报导出证据 JSON（id/时间/发送者/原文）；隐私设置写明互惠关系；回执/在线/输入支持「对某人例外」（本地）。
**优先级**：P1。

## 七、安全可验证性、状态质量与可达性

### 13. 没有安全码/密钥指纹与密钥变更提示
**现状**：房间口令派生静态密钥，客户端不展示任何可核对指纹；对方换口令/换设备无提示，只能靠「看不到消息」自己猜。
**对标**：Signal Safety Number、WhatsApp 安全码、Telegram 加密聊天密钥表情。
**建议**：Host 暴露房间 topic 的短指纹，资料卡/房间设置展示并支持对读验证；本地记录上次指纹，变更时横幅警告「房间密钥已变化」；文案明确「换口令 = 新房间」。
**优先级**：P2（依赖 Host 提供指纹，不改加密协议）。

### 14. 空态/加载/错误仍有裸奔面
**现状**：消息区已有 skeleton；会话列表、搜索、群资料、设置分区首载仍是空白或纯文字；请求失败只有全局 banner，没有区块级重试；切换会话的旧快照与新请求之间没有区分 loading 占位。
**对标**：Telegram 骨架屏、Slack 分栏 loading、Discord 全屏 skeleton；各区块独立 error + retry。
**建议**：会话列表/搜索/群资料补 skeleton；数据区块统一包 `AsyncBlock`（loading / empty / error / retry）；切会话按 key 重置滚动并显示占位；错误块支持「复制诊断信息」（Host 地址、时间、错误码）。
**优先级**：P2。

### 15. 无障碍与移动端可达性
**现状**：有焦点陷阱、aria-live、焦点环、reduced-motion；但消息列表没有 roving tabindex/方向键导航，Tab 要逐个穿过每条消息的操作按钮；浮层关闭不归还焦点；移动端没有 safe-area、`100dvh`、visualViewport，iOS 键盘可能遮住输入区，也没有滑动/长按手势（与 #1 同源）。
**对标**：Slack/Discord 键盘导航，Telegram Esc 返回；移动端键盘跟随/safe-area/滑动手势。
**建议**：消息列表改 roving tabindex（↑↓/Home/End，Enter 开菜单），操作按钮 `tabIndex:-1` 收敛 tab 序；浮层关闭归还触发者焦点；`100dvh + env(safe-area-inset-bottom) + visualViewport` 处理键盘；补滑动/长按；字号跟随 DSH token 并支持 A-/A+。
**优先级**：P0（移动端键盘遮挡）/ P1（键盘导航）。

## 八、排期建议与验收

- **P0**：#1、#15——触屏与键盘可达性、手机键盘遮挡，直接决定「能不能用」。
- **P1**：#2–#12——高频交互对标差距，建议分三批：M1 消息与搜索（#2/#3/#6/#7），M2 输入与通知（#8/#9/#10），M3 会话与群/隐私（#4/#5/#11/#12）。
- **P2**：#13、#14，以及 RTL、字号/密度；多设备同步、消失消息、设备验证属协议项，不在本轮 UI 范围。

**验收方式**：移动模拟 + iOS/Android 真机过消息菜单、键盘、滑动；键盘只用键盘完成「开会话→读消息→回复→搜索→跳转→关浮层」并检查焦点；浅/深色、200% 缩放、360/390/414 宽度回归；jsdom 覆盖菜单、搜索跳转、通知合并，i18n 新增 key 双语对齐。
